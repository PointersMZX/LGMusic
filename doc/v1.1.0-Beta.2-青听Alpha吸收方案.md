## 一、Alpha 调研结论（可用素材）

1. **沙箱协议升级**：alpha 的 `assets/script/user-api-preload.js` = lx 协议 **v2.0.0**（QuickJS），相对我们现版新增：
   - `URLSearchParams` / `Promise.any` polyfill（脚本侧可用）
   - 线路表加 `qs`（汽水，仅展示+musicUrl，可播性由上层判断）；`supportActions` 加 `xm`
   - 音质表全线扩为 `128k/320k/flac/flac24bit/hires/atmos/master/atmos_plus`（qs 加 `spatial`）
   - 原生函数面不变（set_timeout/str2b64/b642buf/str2md5/aes/rsa 七个，我们 QuickJS.java 已全暴露）→ **preload 可直接整体替换**
2. **音源配置体系（B 型对接目标）**：
   - 「青听音源配置」为**配置列表**（可多份、可排序拖动、可启用/关闭、本地导入+网络导入、「获取青听音源配置」从服务拉取）
   - 端点（从 bundle 字符串确认）：`music.haitangw.cc`（banner/update.json/MV·KGMV/KWMV/WYMV/qqmv/quality 尺寸）、`musicserver.haitangw.cc`（resolve-url 解析网关）、`qt.haitangw.net`
   - 行为：内置搜索线路（client 直连各平台公开 API：kugou weapi/mobilecdn、163 weapi、qq fcg、bili WBI 等）+ **解析失败自动回退青听网关**（「当前文件来源暂不支持直接…解析将回退青听网关」）
   - 新特性（下一轮清单见 §五）：服务线路测速/自动选最快、「平台首选音源」（某平台固定指定某音源）、本地解密（`libyibaiqmc.so` = QMC 解密 native 模块）、边听边缓存（我们 10-05 已做）、音源拖动排序、实验室页
3. **UI 素材（字符串层）**：首页「欢迎来到…」+ 榜单（新歌榜/古风榜/民谣榜等分类型榜）、「我喜欢的」（搜索结果/播放页点 ❤ 归集，我们已有 LOVE 列表，对齐即可）、歌单分享、「仅显示下载中的记录/仅成功记录」下载过滤、主题取色（饱和度/亮度滑杆）、背景图片来源选择、蓝牙歌词（车机场景，低优先）

## 二、音源方案定稿

### A 型 · JS 音源（重写 publish/source/星雨音乐-官方音源A型.js）
**合而选优 = 青听（协议 v2.0.0 + 网关回退架构 + 档位映射）× 落雪（各平台直连公开端点 + 回退链）**：
- 六线：星记 kw / 星芸 wy / 星腾 tx / 星犬 kg / 星谷 mg / 星宝 bili
- 每线解析链：**直连优先 → 青听渠道网关兜底**（与青听 alpha 同款行为）：
  - bili 直连：B 站公开 playurl（dash audio，已验证，网关无 bili 线故 bili 永远直连）
  - wy 直连：music.163.com 公开 API（128k/320k mp3 + lyric/封面）
  - kw/kg/tx/mg：公开直连端点不可靠 → 直接走网关（不冒进）
  - 网关常量 `RESOLVE_URL` 置顶，青听作者换接口时改一处（与 B 型同源）
- 45s URL 缓存；档位映射与桌面 qingCloud 一致（standard/exhigh/lossless/hires→128k/320k/flac/flac24bit，bili192→192k）
- init 声明：各线 qualitys 取与 App `LX.Quality` 并集（128k/320k/flac/flac24bit/192k），actions=musicUrl
- 沙箱兼容：桌面 user-api 与移动 QuickJS 同一 lx API 面，一份 JS 双端可用

### B 型 · 青听官方音源（改名「星雨音乐官方音源」，接口对接青听）
- `publish/source/星雨音乐-官方音源B型.json` 扩 schema：
  ```json
  {
    "name": "星雨音乐官方音源 · 青听渠道",
    "interface": "qingting",
    "gateway": { "resolve": "https://musicserver.haitangw.cc/v1/music/resolve-url", "timeout": 12000 },
    "lines": [ {"id":"kw","name":"星记","displayName":"酷我","levels":[...],"enabled":true,"quality":"exhigh"}, ... ]
  }
  ```
  - `lines.id` 保持青听原生（qq=QQ音乐），app 侧映射 qq→tx（不变）
  - `gateway` 字段化：青听作者对接后的正式接口只需换 JSON（或 app 默认值），代码不动
- 桌面 `qingCloud.ts`：`RESOLVE_URL` 改为读配置 gateway（缺省回现值），校验/构造逻辑不变；i18n 文案改「星雨音乐官方音源 B 型（青听渠道）」
- **移动端新增 B 型导入**（对齐桌面两卡片）：设置→基础→音源 = 「A 型 · JS 音源」+「B 型 · 官方音源（青听渠道）」两卡片；.json 本地导入 + 启用/关闭 + 各线状态；存储 `source.qingtngConfig`/`source.qingtngEnabled`（与桌面同键，备份互通）；移动端移植 qingCloud（resolve-url 客户端 + 45s 缓存 + 档位映射），挂虚拟源 `user_api_qingcloud`

## 三·B 播放器页重构（PowerAmp build-988 × 液态玻璃，移动为主，桌面跟随）

> PowerAmp 素材（_tmp/pa988_pairs.txt，aapt2 资源表原样名）：它的 UI 精华 = **Player Screen 底片模型 + 波形拖拽 + 背景模糊四参数 + 全局色定制 + 队列手势**，与我们 WebGL 液态玻璃叠加即成目标效果。

核心设计（播放页=全屏/半屏 bottom sheet，紫金黑 xingyu 主题玻璃叠层之上）：

1. **背景层 = 液态玻璃**：当前栅格化主题背景 → 改为「当前封面/专辑图经 WebGL 折射+色散」的活玻璃面（LiquidGlass 组件已移植自桌面，移动 `c-glass-*` 键复用）；封面作折射源，玻璃参数（磨砂/折射强度/色散）随主题 xingyu 锁死，自定义主题可关。对齐 PowerAmp「背景模糊/细节/强度/饱和度」四参数 → 映射到玻璃的（磨砂/折射/光晕/色散）四滑杆（设置-主题下，下一轮）
2. **波形进度条（Wave Seek）**：PowerAmp 招牌——进度条渲染为音频波形峰柱（`h_main_waveseek=Drag bars to seek`）：拖动柱=精确 seek、点空白=跳转、柱色=已播紫金渐/未播灰；数据源=播放引擎波形采样（移动 AudioTrack 峰值缓冲），无波形数据时退化为普通滑杆。**本轮只做 UI 壳**（渐变滑杆+拖动交互，接现有 progress），真波形采样下一轮
3. **封面卡片**：右上角悬浮、圆角+阴影（PowerAmp `album_art_corners/shadow`），可点进播放详情；歌词上滑手势（`swipe album art up to show lyrics`，PowerAmp 同款）切歌词面板
4. **迷你播放条（navbar）**：PowerAmp navbar 手势规格=`按=回播放页 / 左右滑=切上下曲 / 长按=歌曲分类`，加「seekbar in navbar」可选
5. **队列**：播放页内队列面板（enqueue/插入位置/清队/留队，PowerAmp `pref_queue_*` 语义），下一轮
6. **可视化面板**（Milk 频谱）：下一轮评估（需 Milk DSP native，成本高，先不做）
